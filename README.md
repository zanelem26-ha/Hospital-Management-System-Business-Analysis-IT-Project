### Project Background

The Hospital Management System (HMS) was developed as a university IT project to address challenges associated with managing hospital information and workflows.

The project focused on designing a web based system that could support key hospital activities such as patient data management, medicine and prescription management, appointments, billing, and resource management.

The project involved analysing the existing problem context, gathering stakeholder and system requirements, analysing business processes, designing the proposed solution, and planning for development, testing and implementation.

### Project Objective

The main objective of the project was to design and implement a web-based Hospital Management System that could digitise patient records and improve hospital workflows.

The system was intended to support:

- Patient data management
- Medicine and prescription management
- Appointment scheduling
- Billing management
- Resource and inventory management
- Doctor and nurse management
- Improved data security, privacy and compliance

### Project Scope

The project covered the analysis, design and implementation planning of a web based Hospital Management System.

The main areas within scope included:

- Patient information management
- Medicine and prescription management
- Appointment management
- Billing management
- Risk management and inventory
- Doctor and nurse management
- Database and system design
- Security and data protection considerations
- Testing and implementation planning
- User training and handover documentation

The project followed an Agile iterative approach using Scrum, with activities planned across requirements gathering, analysis, system design, development, testing and implementation.

### Project Approach

The project followed an Agile Iterative Model using Scrum. The work was divided into different project phases and iterations covering planning, requirements gathering, analysis, system design, implementation, testing and refinement.

The approach allowed requirements and the proposed solution to be reviewed and refined throughout the project rather than treating the system development as a single activity.
